DOC-01

README & Quickstart

Project Purpose: VolunteerHQ (Problem Card 23) lets event organisers create volunteer shifts, tracks volunteer sign-ups and live check-ins, flags understaffed roles in real time, and recommends skill-matched replacement volunteers when last-minute dropouts occur.

What to Click Within 30 Seconds: Use the dark 🎯 30-Second Judge Verification Bar at the top of the page and click buttons 1️⃣ → 2️⃣ → 3️⃣ in order.

No-Secret Setup Steps: 100% browser-first single-file app (index.html). Double-click index.html or open the GitHub Pages URL. Zero .env files, zero installs, zero external APIs.

Pre-Loaded Demo Data: Ships with 3 fictional shifts (Registration Desk, AI-ML Lab 4 Runner, Refreshments Counter) and 5 fictional standby volunteers.

Known Limitations: State persists locally per browser tab via localStorage; SMS/WhatsApp alerts are intentionally simulated via the in-app Dispatch Log per competition rules.

Judge Runbook (60-Second Demo Script)

  1. Starting State (0–10s): App loads immediately with 3 fictional shifts (6 / 7 total capacity filled) and 1 pre-triggered understaffed shift in AI-ML Lab 4.
  2. Action 1 — Role Capacity & Check-In (10–25s): Point to Registration & Welcome Desk (3 / 3 capacity). Click Check In next to Kabir Menon (Mock). Expected Output: Checked-in counter increments to 3 / 3 and logs in the Audit Feed.
  3. Action 2 — Where the Twist Appears (25–45s): Click "2️⃣ Step 02: Simulate Last-Minute Dropout" (or ⚡ Simulate Last-Minute Dropout on any shift). Expected Output: A volunteer cancels, the card border pulses red with an UNDERSTAFFED alert banner, and the Minute 40 Twist Intelligent Replacement Box appears inside the card.
  4. Action 3 — Intelligent Reassignment (45–60s): Click "3️⃣ Step 03: Auto-Reassign Best Replacement" (or ✨ Reassign & Check In). Expected Output: The highest-scoring available volunteer is reassigned and checked in, turning the card green (✓ FULLY STAFFED).
  5. Simulated Features Note: Volunteer notifications are simulated via the on-screen Local In-App Dispatch Log (no external SMS/WhatsApp APIs used).

Five-Test Checklist

2. Happy Path Test: Create shift "Stage Mic Runner" (Capacity: 2), sign up a volunteer, and toggle Check In. Expected: Shift appears, capacity updates, check-in badge turns green.
3. Twist Check (Dropout & Reassign): Trigger last-minute dropout on a staffed shift, then click Reassign & Check In. Expected: Card turns red (Understaffed), ranks replacements, and restores full capacity.
4. Reset / Refresh Check: Modify shifts, refresh browser (F5) to verify localStorage persistence, then click 🔄 Reset Demo. Expected: State survives refresh and cleanly restores defaults on reset.
5. Boundary Case Test: Attempt to trigger dropout on a shift with 0 volunteers, or enter capacity 0 / >25. Expected: Gracefully blocked with a warning banner; no negative counts.
DOC-04

User Quickstart (4-Step First-Time Guide)

  1. What the App Does: VolunteerHQ is an all-in-one command center for college event organisers to create volunteer shifts, check in volunteers on arrival, spot understaffed roles, and auto-fill last-minute dropouts.
  2. What Input to Provide:
    • Organisers: Enter Role Title, Shift Time Window, Venue/Zone, Required Capacity (1–25), and Skill Tag in the left form.
    • Volunteers: Type a fictional name in any shift card's bottom input box and click + Sign Up.
  3. What Result to Expect: Instant recalculation of top capacity metrics, live progress bars on shift cards, red pulsing alerts when a role is understaffed, and ranked replacement suggestions.
  4. How to Recover from a Mistake: Made an accidental check-in? Click Undo Check-In. Dropped the wrong volunteer or cleared the pool? Click 🔄 Reset Demo in the top bar to restore the clean starting state immediately.
DOC-05

Data & Privacy Note

Stored Fields Schema: shifts[] (id, role, time, location, requiredCount, skillTag, lastDropout, volunteers[{name, checkedIn, skill}]), availablePool[] (id, name, skill, currentStatus, freeWindow, reliability), and auditLogs[].

Local Browser Storage Only: All state is stored strictly inside the user's browser via window.localStorage keys (vhq_win_shifts, vhq_win_pool, vhq_win_logs).

100% Fictional / Mock Data: All pre-loaded and user-added names use fictional identities tagged with (Mock). No real student PII, phone numbers, or emails are collected.

Zero External Network Transmission & No Secrets: The app never sends form inputs, attendance records, or messages to any external server, database, or SMS/WhatsApp API. Confirmed: zero API keys, zero tokens, and no .env files are included anywhere in this project.

DOC-06

Handoff & Limitations

Main Files & Components: Self-contained in index.html alongside repository documentation (README.md, PRD.md, ARCHITECTURE.md, AGENTS.md, TASKS.md, DECISIONS.md, CONTEXT.md).

Where Core Logic Lives: Inside the embedded ES6+ <script> block: renderAll() handles real-time capacity math, simulateDropout() triggers the Minute 40 Twist, and getIntelligentRecommendations() scores standby + cross-shift replacements.

How Demo Data is Reset: Clicking 🔄 Reset Demo invokes resetDemoData(), overwriting localStorage with deep-cloned defaultShifts and defaultAvailablePool arrays.

What is Deliberately Mocked: Multi-user concurrency, authentication, and SMS/WhatsApp push notifications are mocked via the local Dispatch Audit Log.

Top 3 Improvements for Production Deployment: 1. Real-time multi-device sync via WebSockets/Firebase/Supabase so multiple organisers see check-ins simultaneously. 2. Role-based authentication separating Organiser Admin views from QR-code Volunteer self-check-in views. 3. Automated calendar time-overlap parsing and opt-in push/email shift reminders.
